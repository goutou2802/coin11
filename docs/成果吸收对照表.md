## 三、这次额外做的两件事（不来自归档，来自现场）

1. **自适应停留**（用户 2026-11-02 现场反馈：「浏览任务不用点进商品页，在页面滑动就行了，
   进去时间就在减少，可能不滑动都行」）
   原实现一律连滑 N+1 秒。现在：落地后**先不动**，隔 2.5s 取两帧，只 OCR 上半屏比对
   倒计时数字 / 进度 n/m / 页面数字集合：
   - 在变 → mode=wait，**全程只等待**（每轮省 10~17 秒，也少了误触）
   - 没变 → mode=swipe，开始滑，每 3s 复查一次，**一变就停手改等待** → mode=mixed
   - 玩N秒 / 去逛 → want=static，根本不许滑
   verdict 里记 dwell_mode 与 basis（判断依据），probes 记每次采样的读数；
   --force-swipe 可退回老行为。函数：adaptive_dwell / dwell_signature / _sig_changed
2. **两处口径修正**：① 点后首次读到的前台可能是旧 App（landing_after 复核）；
   ② 弹窗探针不再把页面静态文字当弹窗（popup_probe）。两条都是从归档脚本里学来的。

## 六、真机实跑发现并修掉的两处（2026-11-02 12:30，手机1 192.168.1.8:5555）

这两处不是从归档里读出来的，是拿 auto.py 真跑时**当场撞出来的**，修完都留了源注释：

1. **停手时没写 verdict**（证据链会断）
   one_round 里 StopRun / NeedTeaching 是直接 re-raise 的，那一轮只落了 01~05，没有 06_verdict。
   真机实证：_smoke/race3/rounds/round-001 只有五件，报告里就是「有证据、没结论」的空轮。
   修法：re-raise 之前先写一条 status=stoprun 的判定；repair_missing_verdicts 继续在下次启动兜底。
2. **教过的「返回」规则会把真正的 BACK 挡掉**
   back_to_panel 里 click_by_rule 只要点到就返回真，于是 dev.back() 永远不执行 —— 真机上
   4 次 BACK 全变成点 (95,249)，面板永远回不去（那一页是淘宝宝图片搜索页，那个坐标不是返回键）。
   修法：规则只试第一次，之后一律 keyevent BACK（对齐 logs/r2back.py：那边从头到尾只用 keyevent）。
   附带：筛选后仍回不到面板 → am start 拉回 → 仍认不出入口 → 落 pending 停下来等人教（退出码 3），
   宁可问人也不瞎点 —— 这条设计在真机上被验证到了。

## 七、2026-11-02 追加：用户批准 / 要求的两项（本次已实现）

### 7.1 导航弹窗熔断（用户批准的修法）
问题：从桌面起跑时，首页双11 大 banner 会被 find_popup_card 当成弹层 → 关掉 → BACK → 又回首页
→ 再判弹层，nav 一直循环到预算耗尽（真机 race6 那轮 12:42 就是这样）。
修法：给每次「判到的弹窗」一个稳定指纹（卡片矩形 + 关闭文案 + 前台），**同一指纹连续 3 次**
（POPUP_BREAKER_LIMIT）就熔断 = 当「认不出入口」→ write_pending + 停手（退出码 3），不再烧预算；
中间换过卡 / 换过页面就清零。函数：popup_signature / popup_breaker，接在 nav_until_panel 的弹窗分支里。
自测：T21。

### 7.2 跳转确认框按用户授权点（用户要求）
用户原话：「那个如果选了始终打开后面就不会跳了，就是直接到软件了」。
面板把选择写进 coin11/targets/jump_policy.json（**写方是 dash.py，实际键名是 policy，不是 mode**）：

    {"policy": "once" | "always", "label": "...", "updated_at": "...", "by": "页面",
     "targets_for": ["192.168.1.8:5555", "192.168.1.5:43059"]}

auto.py 现在读这个文件：once → 点「仅打开一次」，always → 点「始终打开」；
文件不存在 / 值写坏 → 一律按 once（更保守：多确认一次，不替用户决定「以后都别问」）。
只在「打开其他应用 / 即将跳转」这类确认框自己出现时出手，只点用户选的那一枚；
那枚读不到就如实返回 not-handled（不改点「取消」、不改点另一枚）；
**安装页 / 权限页不在授权范围**，照样由看门狗拦下等人。
接线：one_round 点行前（01/02 帧）与点行后（04/05 帧）各判一次，点掉后重新取证。
函数：load_jump_policy / jump_dialog_button / handle_jump_dialog。自测：T22。

> 注：本会话没有创建该文件，读的是面板已经写好的那一份（policy=once，12:40 由页面写入）。
### 7.3 浮层关闭白名单（用户 2026-11-02 批准）
允许点的「关掉挡路浮层」文案：确认选择 / 我知道了 / 取消 / 以后再说 / 暂不 / 关闭 / ×
（这些只关浮层，不产生任何交易或授权）。已知案例：**解锁新车轮弹窗不能用 BACK（会掉回首页），
必须点「确认选择」** —— 所以 back_to_panel 里遇到这类浮层先试点批准的关闭文案，读不到才退 BACK。
仍然绝对禁止点：立即领取 / 领取 / 去支付 / 开通 / 授权 / 同意 / 签约 / 抽奖 / 去使用 / 去玩 / 抢
（POPUP_HARD_FORBIDDEN；另保守追加 支付 / 去逛逛 两条历史事故词）。
短词按**整串相等**认，「取消订单并退款」这类长文案不会被当成关闭键。
函数：OVERLAY_CLOSE_WORDS / OVERLAY_CLOSE_EXACT / overlay_close_button，close_candidates 同步认这批词。
自测：T23。
