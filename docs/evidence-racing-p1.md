## 4. 每一行的形态归类（6 形态 + 1 个越界）

### 4.1 归类结果（run1 行号）
```
第1行 好物随心逛        (8/10)  浏览15秒   -> BROWSE_SECONDS   (dwell=15)
第2行 去快手打卡领手机  (0/1)   点击去逛   -> VISIT_JUMP       (跨App: 快手)
第3行 搜一搜你心仪的宝贝(0/10)  浏览15秒   -> BROWSE_SECONDS   (dwell=15)  ← 名字是"搜一搜"，副标题才是真形态
第4行 你关注的商品都可抵(0/1)   浏览15秒   -> BROWSE_SECONDS   (dwell=15)
第5行 逛一逛支付宝金豆夺宝(0/1) 点击去逛   -> VISIT_JUMP       (跨App: 支付宝)
第6行 好物沉浸看        (0/5)   浏览15秒   -> BROWSE_SECONDS   (dwell=15)
第7行 搜一搜你喜欢的宝贝(0/5)   浏览5秒    -> BROWSE_SECONDS   (dwell=5)
第8行 每拉1人最高2000能量(0/10) 邀请好友成功助力最高得 -> **越界**（6形态之外）
```
汇总：BROWSE_SECONDS **6 行**、VISIT_JUMP **2 行**、QUIZ **0**、SEARCH_RETURN **0**、CLAIM **0**（行内）、NEVER **0**、越界 **1 行**（拉人助力）。

### 4.2 归类依据（全部来自副标题原文）
- `浏览15秒` / `浏览5秒` → 唯一动作是「停留 N 秒」，N 直接写在副标题里（15 / 5 两种，不是固定值）→ BROWSE_SECONDS，`motion` 需 swipe_loop（RETRO 证伪3：静止白等计数不动）。
- `点击去逛` → 点一下就跳，落地在外部 App（快手 / 支付宝）→ VISIT_JUMP。
- 第 3、7 行名字带「搜一搜」，**但副标题是「浏览15秒/浏览5秒」**，不是「从首页入口或搜索回访」。
  → 按 ARCH §2「形态从副标题读，不从任务名读」，它们是 BROWSE_SECONDS，**不是 SEARCH_RETURN**。
  这是本次最容易踩的假归类。
- 第 8 行副标题 `邀请好友成功助力最高得`：既非浏览也非跳转，需要**另一个真人点助力**，任何单机动作序列都无法完成
  → 建议新增形态 `INVITE_HELP`（或直接归入 NEVER 并记录原因）。ARCH 的 6 形态表覆盖不到它。

**对用户反馈的裁决**：用户说「很多是一样的，只是描述不一样」——
- 证实：**浏览类 6 行 + 跳转类 2 行**，这 8 行里的动作与淘金币的浏览/跳转完全同构（动作可复用，与 ARCH 一致）。
- 证伪：淘金币的三个**不可替代**形态（下单得 / 答题 / 回访）在赛车能量面板里**一行都没有**；赛车多出一条「拉人助力」。
  所以不是「同一张表换了描述」，而是「**同一套动作原语，不同的形态组合**」。
- 追加证据（比文案更硬）：**同一 (n/m) 计数会在不同名字之间搬家**。
  run1：`好物随心逛(8/10)`，run3：`搜一搜你心仪的宝贝(8/10)` 而 `好物随心逛` 变 `(0/10)`；
  `搜一搜你心仪的宝贝` 在 run2 里是 `(0/5)`、在 run1 里是 `(0/10)`。
  → **名字与计数不绑定**，行是「槽位」，计数属于槽位。任何按名字做判据的实现都会错；判据必须挂在计数/状态上。

## 6. 能量 / 余额读数

| 位置 | 能否从 dump 读 | 方式 | 可靠性 |
|---|---|---|---|
| 赛车页 · 加速按钮文案 | **能** | 正则 `剩余\s*([0-9,]+)\s*能量` 打 `升级中 长按可加速升级 松手开始加速升级 升级赛车拿钱 剩余 696 能量 \xa0长按可加速升级` | **连读 3 次 = 696/696/696，全一致**（`14-energy-read1.xml` 等，间隔 1s） |

| 能量面板 · 左上角数字 | 不能 | 截图 `12-panel-run1.png` 左上角可见 `696`（与赛车页剩余一致），**dump 里无此文本**（`12`/`15` 两份面板 dump 均无 `剩余`） | 需 OCR；且 `18-panel-run3.xml` 里底层赛车页一起进树时又能读到 696 → **面板态可否读到取决于层级是否进树，不稳** |

## 7. 失败 / 跳走分支（本次实测记录）

1. **页面白屏/塌缩，25s 不自动恢复**：连续 13 次 dump 都是同样 5 个文本节点（只有 `淘金币首页` + 状态栏），
   14:37 那次只剩 9 个文本节点，其中页面自身只有 `回日常版 / 商业化入口 / 去赚能量 / 组队赢` 4 个（其余是状态栏）；
   14:41 更极端：只有 `淘金币首页` + 状态栏（截图 `10-blank.png`）。
   → 处理：`back` 一次 → 「我的淘宝」→ 点「领淘金币」，1.6–2.7s 回赛车页（本次共走 5 段恢复序列，5/5 成功）。
2. **`back` 会把页面带走**：在赛车页按 `back` 直接落到「我的淘宝」（`06-after-back.xml`：67 节点，含 `领淘金币/我的订单/待付款0…`），
   而不是关掉浮层。与 RETRO 证伪6、时序不稳3 一致。
3. **弹层自动消失**：能量面板 / 金币面板都会在几十秒内自己关掉（3 次进面板有 2 次如此），
   届时 dump 只剩 `淘金币首页`；「关闭」按钮随之消失（找不到 `关闭` 节点）。
4. **引导弹窗（`从淘宝首页来访`）**：出现在赛车页下半屏，
   节点为 `从淘宝首页来访` `[476,1596][964,1680]` / `点击淘金币入口或搜索淘金币进入` / `+10` / `Button 回淘宝首页领取` `[60,2820][1380,2976]`，父容器 `[28,1564][1412,2976]`。
   - 与 RETRO 证伪6「弹窗不进无障碍树」**部分不符**：这个弹窗主体**进树**（可见 `visible-to-user=true`），
     只有右上角关闭 X **没有节点**（那一片是空白，无异无障碍元素）。
   - 该弹窗**不覆盖** `去赚能量``[1140,1204][1440,1400]`（弹窗顶边 y=1564 > 按钮底边 1400）。
5. **uiautomator2 选择器 API 不可用**：`d(resourceId="energy_task_button").exists` 返回 False，
   `.click()` 抛 jsonrpc 异常（与服务端 objInfo 通路坏一致，同 `d.info`）。
   → 只能用 `dump_hierarchy()` 本地解析 + `d.click(x, y)`。
6. **一次误触（如实记录）**：run1 之前，我按「01-pre 的 dump」算出 `去赚能量` 中心 (1290,1302) 并点击；
   但同一秒的**截图**显示当时浮在上面的是「赚金币抵钱」金币面板（dump 与截图不同步，见 §1 约束2）。
   点击后出现的正是 `从淘宝首页来访` 引导弹窗（= 金币面板里「从首页回访」那行的引导层）。
   **此后我没有点该弹窗的 `回淘宝首页领取`，也没点任何任务的「去完成」**，弹窗随后自行消失，任务未被执行。
   教训写进结论：**点击前必须"同一个 dump 内"算坐标，并检查覆盖层标记（`做任务赚能量`/`赚金币抵钱`/`回淘宝首页领取`）是否存在**。
7. **面板不可滚动**（见 §1 STEP 3）：`swipe` 后行 bounds 完全不变、`scrollable` 节点为 0 → 别写"滚动找更多任务"的分支。
