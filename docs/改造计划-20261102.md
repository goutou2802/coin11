### 7.2 共享契约（两边都必须照这个实现，字段名不许各写一套）

**A. 脚本定义** `coin11/scripts/<id>.json`（一脚本一文件）
```json
{"id":"jd_signin","name":"京东每日签到","created":"2026-11-02T18:00:00","updated":"2026-11-02T18:05:00",
 "order":10,"enabled":true,"note":"先手动把京东打开到首页",
 "steps":[
   {"op":"wait","secs":2.0,"note":"等首页加载"},
   {"op":"tap","x":720,"y":1500,"note":"点签到"},
   {"op":"back","note":"返回"},
   {"op":"swipe_down","x1":720,"y1":900,"x2":720,"y2":1900,"dur":250},
   {"op":"home"}
 ]}
```
- `op` 只能是：`tap` / `back` / `home` / `recents` / `swipe_up` / `swipe_down` / `wait`
- `id` 只许 `[a-z0-9_]`，由 dash 从名字生成或用户填；文件名 = id + `.json`
- `order` 小的先跑；同 order 按 id 排

**B. 面板完成记忆** `coin11/state/panel_done.json`
```json
{"v":1,"panels":{"coin":"2026-11-02","race":"2026-11-02"}}
```
- auto.py 在某面板**走到「到底」收工**时写入当天日期（`datetime.now().strftime("%Y-%m-%d")`）
- 启动时读：该面板日期 == 今天 → 跳过并写日志「今天已完成，跳过（用【强制重跑】可覆盖）」
- 扫描模式（--what scan）**不读也不写**这个文件

**C. 脚本运行状态** `coin11/state/scripts_state.json`
```json
{"v":1,"runs":{"jd_signin":{"last_ok_date":"2026-11-02","last_try":"2026-11-02T18:10:03",
 "last_status":"ok","last_error":"","steps_done":5}}}
```
- 「每天只成功跑一次」= `last_ok_date == 今天` 的脚本在排队时跳过（手动单跑不受限）

**D. 证据** 每步：`evidence/<日期>-scripts/<id>/<HHMMSS>/step-02_before.jpg` / `step-02_after.jpg`；
整脚本收尾写 `run.json`：`{script_id, started, ended, status, steps_done, error, step_records:[{i,op,ok,ms,before,after}]}`

### 8.6 去掉导航里那次多余的 OCR（2026-11-02 用户质疑「坐标都有还用 OCR 干嘛」）
用户是对的：写死点完之后那 1 次判面板 OCR，和紧接着第一轮 `one_round` 自己抓帧读任务行**完全重复**。
- `written_nav_to_panel(..., judge=False)` / `nav_until_panel(..., judge=False)`：写死动作发完就返回
