## 改了什么

### A. auto.py：规则库优先
- 启动时读 `coin11/targets/targets.jsonl`（`--targets` 可换路径），日志打印 `[rules] 规则库=...（N 条）`。
- `load_rules()` / `find_rule(dev, keywords)` / `click_by_rule(dev, keywords)`：
  按 label/note 关键词匹配，**屏幕 w/h 必须和当前设备一致**，取 ts 最新的一条，命中直接 `input tap`。
- 接入点（都是“先规则、后 OCR 兜底”）：
  - `_nav_action()`：这一屏确实有 去赚金币/领淘金币/我的淘宝/做任务赚能量/去赚能量 文字时，优先用教过的坐标；
  - `dismiss_popup_if_any()` 新增“第 0 级：规则”关弹窗；
  - `expand_panel()`：「展开」优先规则；
  - `back_to_panel()`：回面板优先规则「返回」，不再只按 keyevent 4。
- 命中必打：`[rule] 用规则「返回」点 (95,249)`。

### B. auto.py：未知界面 → 请求教学（退出码 3）
- `write_pending()` 落盘 `coin11/targets/pending/<ts>.png` + `<ts>.json`
  （字段：ts/serial/screenshot/question/context/screen_w/screen_h/state=pending，另加 label_hint/kind/focus/teach_urls）；
  question 是人话；context 含前台包名、已试动作次数、OCR 前 400 字、最近规则、设备尺寸。
- 触发点：认不出入口且无规则可用 / 规则试满仍无进展 / 同一动作 3 次不成功 / 弹窗反复关不掉 / 循环抛异常（也落盘）。
- 停手不再盲点：删掉了“兜底坐标 NAV_MY_TAOBAO 盲点”，认不出入口只走“规则 → am start/BACK 阶梯 → 问人”。
- 变大写提示 + `raise NeedTeaching` → main 返回 **3**。

### C. teach.py：待教学视图
- 顶部标签页 `[实时截图] [待教学 (N)]`；「实时截图」原样保留。
- 「待教学」列出 pending/*.json（state=pending）：缩略图 + question + 时间 + serial + 建议标签；
  点「标注」→ **显示那张历史截图**，标签/备注自动按 label_hint/question 预填。
- 保存：写 targets.jsonl（note 自动带 question 标签、`from_pending` 字段）→ pending.state 改 answered
  （记录 answer 坐标/label/note + answered_at）→ 页面刷新待教学计数。
- 新接口：`GET /api/pending`、`GET /api/pending/shot?ts=`、`POST /api/pending/save`。

### 顺手修的（父会话要求）
- R5 黑名单补：消消乐 / 玩一玩 / 小游戏 / 玩游戏 / 修仙 / 课堂 / 抢 / 红包抢 / 补贴
  （`点击去逛`、`点击商品`、`答题`、`考试` 原本就在）。
  实测：`玩消消乐领金币(0/1)` → `doable=False kind=black why=黑名单词：消消乐`；正常浏览行仍 `doable=True`。
- 另一个会话的符号全部保留：`dismiss_popup_if_any` `find_popup_card` `_region_delta` `_nav_fail`
  `NAV_STEP_TRIES = 3` `赚金币抵钱`；`ast.parse` 通过（2595 行）。
- 天窗：黑帧期间不打断（等 3s×3），再交给 am start/BACK 阶梯；写 pending 的截图会先点屏(KEYCODE_WAKEUP)重拍，避免黑色教学图。

## 已知局限（如实记录）
1. 手机2 熄屏后 screencap 是黑帧，导致验收 2 的教学截图无内容；已加“点亮屏幕重拍”，但那张历史截图无法补救。
2. 手机健康的页面里，am start/BACK 阶梯往往能把导航救回来（手机1/2 都实测过），
   所以教学请求主要发生在“屏幕读不到字 / 同一步骤反复失败 / 弹窗反复关不掉”这几种情况——这是保守设计，宁可多问少乱点。
3. teach.py 的两个实例共用 coin11/targets（pending 也共用）：哪台手机出的问题都能在任一端口看到，靠 serial 区分。
